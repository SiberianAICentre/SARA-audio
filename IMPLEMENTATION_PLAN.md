# План поставки production-пайплайна

Статус: в работе. Дата старта: 11.09.2026.

## Цель

Для каждого входного пакета аудиозаписей построить воспроизводимый GPU-пайплайн:

```text
файлы -> группы operator-year -> канал оператора -> речь без пауз
       -> ASR + признаки + audio/text embeddings -> batch VegaQ1
       -> prediction + feature contributions + demo artifacts
```

Нормативный набор на этом этапе: 92 предметных лингвистических признака из
исходного DOCX. Акустические, ASR- и embedding-признаки
хранятся отдельными блоками, чтобы не менять смысл предметного реестра.

## Общие правила поставки

- Каждый шаг завершается тестами, воспроизводимым артефактом и записью в
  `RELEASE_NOTES.md`.
- Конфигурация, версии моделей, хэши входов и аппаратный профиль сохраняются
  в manifest каждого запуска.
- Отсутствующее или ненадёжное значение не заменяется нулём: сохраняются
  `status`, `reason`, `source` и `confidence`.
- Исходное аудио неизменно; производные WAV и embeddings кэшируются по хэшу
  входа и параметров.

## Шаги

### 0. Контракт и журнал поставки - выполнен

Зафиксировать этот план, журнал релизов, целевые форматы и критерии готовности.

Готово, когда: план и первая release note находятся в репозитории.

### 1. Речь оператора как отдельный вход - выполнен

Расширить подготовку аудио: извлекать второй канал (индекс `1`) без
микширования, проверять наличие двух каналов, выполнять VAD и склеивать только
речевые интервалы оператора в `operator_speech_no_pauses.wav`. Сохранить карту
соответствия фрагментов исходному времени.

Готово, когда: на стерео-тесте ASR, VAD, acoustic extraction используют только
канал оператора; mono-файлы дают явный диагностический статус, а не тихую
подмену канала.

### 2. Входной manifest и пакеты operator-year - выполнен

Добавить manifest-загрузчик с `record_id`, путём, хэшем, оператором, годом и
статусом. Группировать по `(operator_id, year)` и делить каждую группу на
подпакеты размером 15 (настраиваемо).

Готово, когда: каждая запись учтена ровно один раз, порядок детерминирован, а
для каждой группы создан batch manifest.

Windows Server entrypoint перед обработкой готовит поставляемый корпус:
распаковывает только WAV из `test.zip` рядом с `train`, после чего общий вход
содержит оба split.

### 3. Профиль RTX 4090 / CUDA - подготовлен, ожидается smoke-run на сервере

Добавить серверный профиль для CUDA 12: `faster-whisper`/CTranslate2,
`large-v3` или согласованная модель, `float16`, batch size, пути к моделям и
предзагрузку. Добавить диагностическую команду, проверяющую CUDA, VRAM и
реальный device модели; CPU fallback должен быть только явным.

Готово, когда: smoke-run на RTX 4090 подтверждает CUDA и воспроизводимо
транскрибирует канал оператора.

Для запуска корпуса smoke-run обязателен: только результат со `status=passed`
разрешает считать серверный контур готовым.

Для Windows Server подготовлен сценарий копирования проекта без Git:
`scripts/windows/Invoke-SaraServerPipeline.ps1` автоматически создаёт `.venv`,
устанавливает зависимости, запускает smoke-test и затем расчёт корпуса.

### 4. Все 92 предметных признака - реализованы эвристически

Сверить 92 кода с исходным реестром, реализовать признаки слоями: точные
счётчики, русская морфология/синтаксис,
семантические классификаторы. Для каждого кода добавить метод, evidence,
уверенность, тестовые примеры и покрытие.

Готово, когда: 92/92 имеют реализованный расчёт, либо согласованное правило
недоступности для неподходящего входа; нет `source=not-computed` из-за
отсутствующей реализации.

### 5. Признаки ASR и акустики - выполнен

Добавлены агрегаты openSMILE по речи без пауз: `mean/std/min/max` для колонок
из целевых семантических групп, пять первичных ASR-признаков и wide-table с
версионированными именами и раздельной семантикой блоков.

Готово, когда: на файл получается согласованный набор предметных, ASR и
акустических признаков с provenance.

### 6. Audio embeddings Whisper - исключено из поставки до inference 14.09.2026

Whisper encoder output не является speaker embedding: в нём смешаны речевое
содержание, канал записи, фон и голосовые свойства. Он не будет добавляться в
обязательную матрицу VegaQ1 и не блокирует inference. Вернуться к пункту можно
после отдельного пилота и согласования model contract.

### 7. Text embeddings - необязательный следующий этап

Добавить русскоязычный текстовый encoder, embeddings по транскрипту речи
оператора без пауз и версионированный pooling.

Готово, когда: dense text-вектор фиксированной размерности связан с тем же
`record_id` и версией транскрипта. Этот пункт не блокирует inference 14.09.2026.

### 8. Матрица внешней математической модели и интерпретация - отложено

Когда внешняя математическая модель будет подключена, согласовать её входной
schema/порядок колонок, проверку пропусков и версий. Реализовать batch adapter,
сохраняющий prediction, score и вклад каждого признака. Добавить данные для
демо-визуализации.

Готово, когда: один batch проходит model contract, а сумма/смысл вкладов
проверяются согласно интерфейсу подключенной модели.

### 9. Выход, демонстрация и эксплуатация

Сформировать пакет результата: manifest, wide features, embeddings,
prediction, contributions, визуальные данные, логи и отчёт по ошибкам.
Добавить resume, изоляцию ошибок записи и интеграционный тест 15 файлов.

Готово, когда: новый пакет обрабатывается одной командой, повторный запуск
переиспользует кэш, а результат пригоден для сдачи и демо.

Статус поставки серверного результата: реализован отдельный экспорт без
пересчёта. Все табличные материалы передаются одной книгой `delivery.xlsx`, а
служебные manifest/provenance остаются рядом для воспроизводимости.

## Внешние решения, которые понадобятся до шагов 4 и 8

1. Контракт внешней математической модели: формат матрицы, порядок колонок,
   версия модели, формат предсказания и вкладов.
2. Разрешённая модель text encoder и допустимость хранения embeddings.

Эти решения не блокируют подготовку признаков.
